# Julian theme for shadcn/ui + Tailwind

One command applies the Julian look to a shadcn/ui project: the perceptual gray and color scales mapped onto shadcn's semantic tokens, radius 10, the hairline border language, the blue-500 highlight, and the 0.9 press scale on buttons.

## Install

With the shadcn CLI (Tailwind v4 projects):

```bash
npx shadcn@latest add https://juliankellydesign.github.io/julians-guide-to-interfaces/adapters/shadcn/julian.json
```

From a local checkout of this repository, point at the file instead:

```bash
npx shadcn@latest add ./adapters/shadcn/julian.json
```

The CLI injects the variables into your global stylesheet's `:root` and `.dark` blocks and adds the press-state rule. Projects using Tailwind without the shadcn registry can paste [`julian.css`](julian.css) into the global stylesheet below the shadcn setup—same values, no tooling.

## What it maps

Light values come from the design system's documented semantic roles ([`guide/design-system/semantic-tokens.md`](../../guide/design-system/semantic-tokens.md)); every color is an exact stop on the scales in [`data/foundations.json`](../../data/foundations.json).

| shadcn token | Semantic role | Scale value |
| --- | --- | --- |
| `background` | canvas | gray 50 |
| `foreground` | text primary | gray 1000 |
| `card`, `popover`, `sidebar` | surface | gray 0 |
| `primary` | action primary | blue 500 |
| `primary-foreground` | text inverse | gray 0 |
| `secondary` | action secondary | gray 100 |
| `secondary-foreground` | secondary button label | gray 900 |
| `muted` / `muted-foreground` | subtle fill / text secondary | gray 100 / gray 600 |
| `accent` | action secondary | gray 100 |
| `destructive` | danger | red 600 |
| `border` | border subtle (the hairline) | gray 100 |
| `input` | border default | gray 300 |
| `ring` | border focus | blue 500 |
| `radius` | control radius | 10px (0.625rem) |
| `chart-1`…`chart-5` | — | blue, green, orange, purple, red at 500 |

Two mapping judgments worth knowing, both first pass: `accent` (shadcn's hover fill for menu items and the like) uses gray 100 rather than the documented gray-50 quiet hover, because `background` is already gray 50 and the hover would vanish on canvas-level surfaces; and `muted` uses gray 100 for the same reason.

## What it deliberately does not do

- **Fonts.** Karl is personal and not distributed; your type stack survives. The type scale and tracking method live in the guide if you want them.
- **Spacing and type utilities.** Tailwind's scales stay yours—the theme overrides color, radius, and the press state, not your layout language.
- **Dark mode taste.** The `.dark` block is a mechanical first pass: the same scales with roles mirrored and elevation preserved. The guide documents no dark-mode opinion yet.

## Brand hue

Scaffold semantics apply. If the host has a real brand hue, don't ship blue 500—feed the hue through the color-scale recipe (`guide/methods/color/perceptual-color-scales.md`) and regenerate `primary`, `ring`, and their kin from it. The lightness and chroma curves are what make the look; the hue is yours.

## Regeneration

`julian.json` and `julian.css` are generated by [`scripts/generate-adapters.py`](../../scripts/generate-adapters.py) from `data/foundations.json`. Don't edit them by hand; change the guide, then regenerate.
