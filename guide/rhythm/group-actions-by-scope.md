# Group actions by scope

## In brief

Related elements should do related things. When actions are grouped visually, the grouping should communicate a shared context, object, or scope.

## Make visual grouping match functional grouping

Proximity, alignment, enclosure, and shared visual language tell people that elements belong together. The actions inside that group should operate on the same part of the interface or represent comparable ways to complete the same task.

A row of buttons in a modal should relate to the modal. A stack of actions in an onboarding step should relate to that step. Placing an action inside the group implies that it belongs to the same decision.

## Separate actions with broader scope

Suppose an onboarding step asks someone to add profile details. “Import profile” and “Manually enter” can be stacked because both actions provide a way to add those details.

“Skip” applies to the onboarding flow more broadly rather than to the task of entering profile details. It may still be understandable inside the stack, but placing it separately—such as in the top right—communicates its broader scope more accurately.

## Keep completion actions with their inputs

An action that submits or sends an input belongs with that input. Place the button inside the field or directly beside or below it. Distance from the input weakens the relationship and makes the action’s target less clear.

## Use reading order to explain sequence

For left-to-right, top-to-bottom interfaces, arrange related elements according to what should be understood or completed first and what should happen afterward.

The primary choice in a group often needs to be encountered first. A completion action follows the content it acts on: someone enters text, then reaches the send button. Adapt the direction for other writing systems, but preserve the intended sequence.

## Working rules

- Group actions only when they share a context, object, or scope.
- Use proximity, alignment, enclosure, or shared visual language to communicate the relationship.
- Separate actions that apply to a broader or different part of the flow.
- Keep submit and send actions close to the input they act on.
- Arrange grouped elements so reading order matches the intended interaction sequence.
- Adapt spatial direction to the interface’s writing system.
