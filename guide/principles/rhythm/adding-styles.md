# Ask twice before adding a style

## In brief

When I'm adding elements and need a new style, I ask myself two questions: have I seen something similar elsewhere in the interface before, and can the new thing I'm designing be repurposed elsewhere. The first question looks backward for something to reuse; the second designs the addition for reuse. Both keep treatments bound to types rather than instances.

## The backward question

Before inventing, look for a similar treatment already in the interface. If one exists, use it: the reuse costs nothing, the element inherits an already-taught meaning, and every repetition strengthens the pattern for the next reader. A new style that duplicates an existing one's job splits the system without communicating anything.

## The forward question

When nothing similar exists and the style is genuinely new, design it to be repurposed. A style shaped for one instance is a one-off—it will fit nothing else, and the next similar need will spawn another one-off beside it. A style shaped as a type earns its future uses at the moment it is added.

## Treatments bind to types, never to instances

The same rule already runs through the guide in different coats: an attention shadow applies to every element of its type, never one instance; a second everywhere-icon-size means the icon system has split; a color keeps one meaning wherever it appears. They are one principle. A treatment attached to a type is a signal the interface can teach; a treatment attached to an instance is an exception the reader must forgive.

## Working rules

- Before adding a style, look for a similar treatment elsewhere in the interface and reuse it.
- When adding a genuinely new style, design it to be repurposed rather than fitted to one instance.
- Bind every treatment to a type; never style a single instance.
- Treat a growing number of one-off styles as a sign the two questions are being skipped.
