# Nest a button inside an input when it acts on the content within

## Status

A musing. This is a lean I keep returning to, not a settled principle. Treat it as a soft default and revisit it as examples accumulate.

## In brief

I often wonder whether the right move is to nest a button inside an input or have it exist outside. The lean: buttons are best nested inside inputs when they take action on the content within—a send button inside a composer, a submit inside a search field. A button whose action reaches beyond the input's content stays outside.

## Why the lean holds

Visual grouping implies functional grouping, and nesting is the strongest grouping claim an interface can make: placing a button inside the input's boundary says this button acts on this content. When that is true, nesting communicates the scope precisely. When the button does something broader, nesting borrows a claim it cannot keep—the same reasoning that keeps broader actions out of a task's control group.

## Working lean

- Lean toward nesting a button inside an input when it acts on the input's content.
- Keep a button outside the input when its action reaches beyond that content.
- Treat this as a musing; note examples that confirm or strain it.
