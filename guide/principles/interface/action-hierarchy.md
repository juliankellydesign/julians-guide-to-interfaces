# Give actions a clear hierarchy

## In brief

Highlight one primary action on a surface, then reduce the visual prominence of every other action according to its importance. Keep grouped actions to two or three levels of hierarchy so the next action remains clear.

## Choose one primary action

A surface should almost always have one primary action. The primary action communicates the most important thing a person can do next.

In a chat composer, the send button is primary. Its filled or contrasting background makes it more prominent than the controls around it.

Secondary actions remain available without competing for the same attention. An attachment button might use a stroke or a subtle background. A model selector or another supporting control can be tertiary and quieter still.

A surface can contain as many secondary actions as it needs. The constraint is not the number of available actions. The constraint is visual competition: only one action should read as primary across the surface.

## Limit the number of levels in a group

Use no more than two or three levels of hierarchy among actions that are visually grouped together. One primary action, one or two secondary actions, and one tertiary action are usually clearer than adding a quaternary level to the same group.

Distance and grouping change the comparison. When actions are placed farther apart or separated into distinct containers, the interface can support additional local hierarchies because the actions no longer compete as one group.

## Keep grouped controls the same size

Actions grouped together should generally use the same control size. Communicate hierarchy through fill, contrast, and stroke before changing dimensions.

Consistent sizing establishes that the controls belong to one interaction. Their visual treatment then communicates which action is primary, secondary, or tertiary.

## Resolve competing calls for attention

When another element needs attention on a surface that already has a primary action, decide in this order:

1. Confirm which action is actually primary.
2. Determine whether the competing element is better communicated as an error, warning, or notification. An invalid form field is a state that needs correction, not a second primary action.
3. Use grouping or size to separate actions that belong to different scopes.

Do not make several controls look primary because several things matter. Express their different jobs with the appropriate visual language.

## Separate persistent and local actions

A persistent highlighted action can coexist with the primary action on the current surface when its scope is visibly different. For example, a highlighted action in a tab bar can use the tab bar container and a difference in size to distinguish it from the surface’s primary action.

The separation should make the two actions read as belonging to different systems rather than competing inside one group.

## Working rules

- Highlight one primary action on a surface.
- Include as many secondary actions as the surface requires without making them compete with the primary action.
- Use secondary and tertiary treatments to communicate the importance of other actions.
- Keep a visually grouped set of actions to two or three hierarchy levels.
- Prefer one primary, one or two secondary, and one tertiary action to adding a quaternary level.
- Keep grouped controls the same size unless size communicates a difference in scope.
- Use fill, contrast, and stroke to establish hierarchy within a group.
- Treat errors, warnings, and notifications as states rather than additional primary actions.
- Use distance, containers, or size to separate action hierarchies that belong to different scopes.
