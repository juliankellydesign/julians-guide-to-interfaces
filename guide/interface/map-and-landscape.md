# Design both the map and the landscape

## In brief

The product’s functionality is the landscape a person must navigate. The interface is the map that explains that landscape. Use familiar conventions to make the map readable quickly, then use internal consistency when no established shorthand exists.

## Distinguish functionality from its explanation

The landscape is the actual terrain: the objects, states, actions, and constraints the product contains. The map is the visual and interactive language used to describe that terrain.

Designing an interface means creating both. A clear map cannot repair incoherent functionality, and useful functionality remains difficult to navigate when the map is inconsistent.

## Begin with conventions people already know

Maps become legible quickly when they use conventions shared with other maps. North stays up and water is blue. Interfaces work the same way: a magnifying glass indicates search, and rounded controls commonly indicate interactivity.

Use an established convention when it communicates the product’s behavior accurately. Familiar shorthand reduces the amount a person must learn before acting.

## Use consistency when no convention exists

Some functionality does not have a widely understood visual shorthand. Define a convention inside the product and apply it consistently.

A map might use dashed red borders for every country boundary. An interface might use a down chevron beside every filename to mean “Open in.” The first instance teaches the convention; repetition allows the person to recognize it elsewhere.

Consistency does not make an arbitrary choice universally familiar. It makes the local map learnable.

## Working rules

- Treat the product’s functionality as the landscape and the interface as its map.
- Use familiar conventions when they accurately describe the action or object.
- Do not invent new shorthand when an established convention already communicates the behavior.
- Define a consistent local convention when no familiar shorthand exists.
- Teach a new convention clearly before relying on its abbreviated form.
- Keep the meaning of a local convention stable throughout the interface.
